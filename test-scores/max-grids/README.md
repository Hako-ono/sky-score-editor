# MAX_GRIDS 10,000 回帰テスト譜面

`MAX_GRIDS = 10_000` の入力上限、通常利用、最大負荷時の防御を再確認するための
生成手順である。JSON本体は大きいためGitへ含めず、必要なときだけ生成する。

## 生成方法

リポジトリ直下で次を実行する。

```sh
npm run generate:max-grids-fixtures
```

スクリプトは各JSONを生成したあと、`parseScoreJson`で読込件数と上限超過警告を
自己検証し、ファイルサイズ、下書き相当のUTF-8サイズ、Node上の参考解析時間を表示する。

| ファイル | 用途 |
|---|---|
| `max-grids-4000.json` | 通常負荷4,000件 |
| `max-grids-6000.json` | 通常負荷6,000件 |
| `max-grids-10000.json` | 正常動作範囲の10,000件 |
| `max-grids-4000-worst-case.json` | 最大負荷4,000件 |
| `max-grids-6000-worst-case.json` | 高速スクロールの回帰確認用6,000件 |
| `max-grids-10000-worst-case.json` | 入力防御の最大負荷10,000件 |
| `max-grids-10001-over-limit.json` | 10,000件への切り詰めと警告 |

通常版は各グリッドに3鍵と短い歌詞を分散して持つ。最大負荷版は両レイヤー各15鍵、
歌詞100文字、2件ごとの強制改行を持つ。生成時の代表サイズは次のとおり。

| 譜面 | JSON | 下書き相当（UTF-8） |
|---|---:|---:|
| 通常10,000件 | 約1.36MiB | 約0.79MiB |
| 最大負荷6,000件 | 約4.45MiB | 約2.54MiB |
| 最大負荷10,000件 | 約7.42MiB | 約4.23MiB |

最大負荷10,000件も10MiBの入力上限内に収まる。解析時間は実行環境で変わるため、
性能基準には使わない。

## 通常の回帰確認

日常の変更では、生成スクリプトの自己検証と次の自動テストを優先する。

- `parseScore.test.js`：10,001件目での打ち切りと警告、異常入力
- `scoreReducer.test.js`：編集経路から上限を超えないこと
- `draftStorage.test.js`：通常10,000件の下書き往復
- `layout.test.js`／`virtualRows.test.js`：全件を失わないPDF用分割と仮想行範囲
- `audioEngine.test.js`：10,000件でもTransportイベント数が定数であること
- `rapidScroll.test.js`：高速タッチ時だけ軽量表示へ入る条件

iPhone実機確認を再実施するのは、仮想スクロールのDOM構造、行高さ・オーバースキャン、
再生スケジューラ、下書き形式・容量、PDF生成経路のいずれかを変更した場合に限る。
単なる文言や他機能の変更では、この大規模試験を繰り返さない。

## 2026-08-30の最終実機確認

公開相当のビルドをiPhoneで確認し、次の3項目すべてに問題がないことを確認した。

1. 通常10,000件の読み込み、1件編集、下書き保存、全範囲再生、BPM・速度・拍子変更、
   ループON、PDF出力
2. 通常10,000件を高速で3往復した際の白画面・強制リロードなし
3. 最大負荷6,000件を高速で3往復した際の白画面・強制リロードなし

最大負荷10,000件の入力、10,001件の打ち切り、異常値、Undo/Redoの組合せは
生成スクリプトと自動テストで確認する。正常動作範囲としての10,000件と、過去に
再現した最大負荷6,000件の高速スクロールだけを実機の最小回帰セットとする。

この確認をもって、10,000件を読み込み専用ではなく、編集・保存・再生・PDF出力まで
含む正常動作範囲として扱っている。
